# stable v0.2.18：GPT-5.5 订阅账号路由调整

本说明对应固定上游目标 `ac1b8f1271be0d674fa6f074403c1410f30a3a81` 的
[行为说明](https://github.com/Wei-Shaw/sub2api/blob/ac1b8f1271be0d674fa6f074403c1410f30a3a81/docs/OPENAI_GPT55_RETIREMENT.md)，不是新版本发布或真实上游账号可用性的承诺。

## 实际行为

- 资格由**上游账号类型**决定，不由客户端访问本服务时使用的 API Key 决定。
  OpenAI OAuth、SetupToken 及其凭据影子账号不能路由到 GPT-5.5；普通调度、黏性调度和 compact 调度一致排除该目标。
- API-key 上游账号不受相同的订阅退役限制。混合组中的 GPT-5.5 请求只能选有实际支持能力的 API-key 账号；非空指针的空模型列表仍是权威结果，不补回默认模型。
- 模型列表、Codex 目录及其 ETag 过滤没有合资格账号支持的退役目标，包括陈旧或固定目录条目。
  先按路由相同的一次映射投影为公开别名，再检查实际目标；不修改共享上游缓存。
- 管理员显式把旧公开别名映射到受支持的新目标仍有效；把其他别名映射**到** GPT-5.5 则不能绕过订阅账号限制。
  诊断到退役订阅目标时返回既有 `model_not_found` 与迁移指引，不静默改写聊天请求到新模型。
- `gateway.openai_compact_model` 保留 API-key 兼容性；订阅请求遇到退役 GPT-5.5 fallback 时跳过该回退，保留选定模型。
  compact 专用映射若显式指向退役目标，该账号不合资格。既有保存配置不会自动重写。

## 管理员检查清单

1. 盘点分组与账号映射、客户端默认模型、自定义代理和定时任务中的 GPT-5.5；区分订阅账号与 API-key 账号，不做全局替换。
2. 在目标上游账号核实替代模型的实际可用性，再修改相应显式映射或客户端配置；本地 fixture 测试不能证明真实订阅权限。
3. 单独检查 compact 映射、`previous_response_id` 黏性会话、公开别名、目录过滤与 ETag；应保留 API-key 账号的合法使用路径。
4. 无需删除 GPT-5.5 价卡、历史用量或公开注册信息，也不应为了订阅迁移误改所有 API 请求。
5. 变更前留存映射与配置，先在隔离环境验收；本文件不授权登录真实账号、发外部请求、修改生产配置或部署。
