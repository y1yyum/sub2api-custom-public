# v0.4.0-rc.1 预发布说明

日期：2026-10-31。关联：[Issue #19](https://github.com/y1yyum/sub2api-custom-public/issues/19)。

本次为 Pre-release，不更新 `0.4` 或 `latest` 镜像标签，不表示生产部署获准。
源码以公开 `main` 的 `01fcc14bf79a93e8f7154b920caca7c3d916b558` 为内容基准，
本次发行准备仅更新版本、版本保护摘要和说明，不改应用逻辑、依赖、SQL 或工作流。
最终标签提交、镜像 Digest、签名和资产以 Release 的真实构建结果为准。

## 相对 v0.3.1 的主要变化

- 整合固定上游 v0.2.18、v0.2.19 的网关、模型目录、计价、账号配额和调度内容，保留二开门户、运行时 OAuth 凭据注入及统一状态页。
- 新增 Scoped 管理员密钥、可选的按图片数量计费、账号用量批量统计与迁移检查工具。
- 调整支付退款审计重试、pending 退款扣减状态及流式响应断连结算，保留对应回归与升级保护。
- 更新门户像素视觉、前端依赖，以及 OAuth 刷新截止时间与取消处理。

## 数据库迁移与部署条件

相对正式版 v0.3.1，新增以下文件；同编号不同文件名是不同迁移，不得重命名或改写已执行文件：

- `246_enable_gemini_image_generation_groups.sql`
- `247_payment_audit_refund_retry.sql`
- `247_scoped_admin_api_keys.sql`
- `248_group_image_count_billing.sql`

部署前必须在脱敏存量数据库副本演练，保留可恢复备份与完整迁移文件名/checksum 记录。
新库冒烟不证明存量升级安全。本次不连接生产数据库，也不声明以下实机条件已经满足：

1. 按[图片分组迁移说明](../upgrades/stable-0.2.18-image-groups.md)捕获并恢复管理员既有禁用策略，验证各实例缓存。
2. 按[支付手册](../upgrades/stable-0.2.18-payment.md)和[退款重试说明](../upgrades/stable-0.2.18-refund-retry.md)冻结旧 worker、逐单对账，禁止新旧 worker 混跑。
3. 按[v0.2.19 兼容说明](../upgrades/stable-0.2.19.md)核对 Scoped Key、迁移账本及图片计费的显式启用策略。
4. 验证实际 Redis、门户支付交互及目标 amd64/arm64 硬件；本地 arm64 仿真不能替代真实硬件验收。

出现异常时先冻结相关处理并保留审计。直接换旧镜像或恢复数据库不能撤销外部已发生的支付/退款，
旧认证代码也不能被假定会执行 Scoped Key 限制；先按上述手册评估前向修复与协调恢复。

## 产物与验证

发布工作流重新执行完整 CI，构建 linux/amd64、linux/arm64 镜像，经冒烟后推送
`ghcr.io/y1yyum/sub2api-custom-public:0.4.0-rc.1`，并生成签名、来源证明、SBOM、离线镜像和校验和。
成功与否以当前标签的工作流和 Release 资产为准，不复用此前本地候选包的版本或 Digest。

下载对应架构的资产后，先在资产目录运行 `sha256sum -c SHA256SUMS`，再用 `docker load -i <镜像包>` 导入。
离线镜像引用为 `sub2api-custom-public:0.4.0-rc.1`；设置 `SUB2API_IMAGE` 后按仓库 Compose 流程运行。
PostgreSQL、Redis 镜像需另行准备。

本次授权范围为打标签和应用预发布；生产部署及上述环境验收不在本次执行范围。
