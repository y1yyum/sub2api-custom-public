Sub2API 0.7.2

相对 v0.7.1，本版新增内置「上游站点」后台模块，统一管理上游钱包余额、余额差值成本、监控与关联账号的调度状态。首次使用从零配置，不导入外部插件数据。

## 功能更新

- 支持 Sub2API、New API、Zivv、DeRouter、Kimi 和 DeepSeek 钱包，提供手动、批量和定时查询；凭据加密保存且不回显。
- 每次成功余额查询更新成本统计：余额下降计入成本，充值不冲抵成本，查询失败不记为零余额；按币种、站点时区展示每日汇总，长时间缺测标记统计质量。
- 人工启用/禁用由按钮操作并显示当前状态，自动控制另用状态点显示；两者独立保存，任一限制存在时均阻止绑定账号参与调度，不覆盖账号自身的禁用及其他限制。
- 支持显式账号绑定、余额/查询失败阈值、只读 JSON 健康探针、事件记录及 SMTP 告警；不增加真实模型调用探针。
- 管理操作沿用管理员认证、审计和二次验证，完善中英文文案、阈值编辑、探针配置及统计保留行为。
- 手动探针请求按配置预算预留完成时间，支持超过 30 秒的有效探针响应。
- 更新像素字体子集以覆盖新增中文文案，并将字体覆盖检查纳入 PR 关键测试及公开 CI。
- 本模块移植自 tokenrouter-upstream-sites，保留模块内来源声明、LGPL-3.0-or-later 许可及其引用的 GPL v3 文本；主项目许可证不变。
- 二进制归档附带模块许可证和来源通知；镜像内对应文件位于 `/app/licenses/upstream-sites/`，主项目通知位于 `/app/licenses/`。

## 数据库迁移

相对公开 v0.7.1，仅新增 `backend/migrations/9012_upstream_sites.sql`，已发布迁移文件未修改或删除。

- 新建 `upstream_site_records` 表、`upstream_site_ids` 序列和到期时间索引，保存站点、绑定、历史、每日统计、事件与告警状态；迁移本身不修改或删除既有业务数据，无需人工转换数据。
- 默认 `DATABASE_MIGRATION_MODE=apply` 时，应用启动自动执行迁移。若采用 DDL/DML 权限分离，先用本版程序和迁移账号执行 `server --migrate-only`，成功后以 `DATABASE_MIGRATION_MODE=validate` 启动应用；可用 `server --check-migrations` 只读核对迁移账本。
- 部署前必须备份 PostgreSQL、`/app/data` 及现有宿主加密密钥配置，保留旧镜像的不可变 Digest。恢复数据库时必须配套保留原加密密钥，否则站点凭据无法解密。不要将密钥写入发布说明、日志或工单。
- 新增表、序列和索引与 v0.7.1 的 schema 使用兼容；启用站点控制后，应用还会在绑定账号的 `extra` 中保存 `upstream_site_restriction`。旧版本不识别此限制，数据库结构兼容不代表调度保护兼容。

## 回滚要求

1. 在 v0.7.2 仍运行时，记录受站点限制的账号及业务期望；需要继续隔离的账号，先通过账号原有人工调度开关禁用，避免旧程序恢复其调度。
2. 关闭各站点的自动查询和自动控制，解除站点人工禁用，并清空所有站点的账号绑定；确认站点限制数为零且账号列表状态符合预期，再停止全部 v0.7.2 实例。只停止查询不足以清理已有账号限制。
3. 使用备份时记录的 v0.7.1 不可变镜像回滚。保留新增表、序列、索引和迁移账本，不执行 DROP，也不删除或改写 `schema_migrations`。旧版本不会提供站点监控、成本更新或站点调度保护；再次升级前核对并按需重新绑定、启用控制。
4. 若新版无法启动而无法完成上述清理，由运维侧先暂停流量和写入，再选择恢复升级前一致的数据库、持久化数据与密钥备份；恢复会丢失备份之后的业务写入，须先评估并保存需对账的数据，不直接修改迁移校验和放行。

测试使用临时数据库和合成凭据，不代表真实生产库升级、恢复或回滚已获验收。

## 部署契约

镜像提供 `linux/amd64` 和 `linux/arm64`，以发布后从 Registry 读回的不可变 Digest 部署。监听地址 `0.0.0.0:8080`、`GET /health` 和持久化目录 `/app/data` 保持不变。本次发布不执行生产部署。
