Sub2API 0.7.3

本版同步上游至 `328db26f4`（v0.2.24 后 1 个提交），整合公开 PR #54、#55。相对 v0.7.2，主要更新如下。

- OpenAI 的 HTTP 与 WebSocket 计费分别记录 30 分钟和 12 小时缓存写入量。渠道显式配置的 12 小时价格优先。渠道仅配置通用缓存写入价时，两档均用该价；渠道未覆盖缓存写入价格时，按模型目录定价。
- OpenAI OAuth 刷新已完成令牌轮换时，在限定时间内按原凭据和代理状态条件写入新凭据。其他迟到响应丢弃，轮换结果写入超时时停止本轮重试。
- 支持按分组启用 OpenAI Ultrafast、按渠道设置倍率。Fable 配额恢复会核对原限流原因和重置时间，保留并发写入的新限流。
- API Key 用量成本查询新增覆盖索引，分组用量日汇总重建期间可继续写入用量。

## 数据库迁移

相对公开 v0.7.2，新增以下五个 SQL 文件。已发布的 SQL 迁移文件均保持原校验和。

| 文件 | 升级影响 |
| --- | --- |
| `249_add_usage_logs_api_key_cost_index_notx.sql` | 并发创建 API Key、时间和实际成本覆盖索引。大用量库需预留索引空间和构建时间。 |
| `250_openai_cache_write_ttl.sql` | 用量日志新增 30 分钟、12 小时两个计数字段，默认零；渠道及统计定价表增加可空的 12 小时价格。历史用量不回填拆分值。 |
| `251_group_force_openai_ultrafast.sql` | 分组新增 Ultrafast 开关，默认关闭。 |
| `251_group_usage_rollup_nonblocking_build.sql` | 增加汇总过期下界、重建边界和最早脏日期，更新用量变动触发函数，以便在重建时记录并发写入。 |
| `252_channel_pricing_ultrafast_multiplier.sql` | 渠道模型定价增加可空倍率；配置的倍率须大于零，留空时使用模型默认值。 |

两个 `251_` 文件按各自完整文件名登记，升级时均须执行。部署前备份 PostgreSQL、`/app/data` 和现有加密密钥配置，并记录 v0.7.2 的镜像 Digest。默认启动自动执行迁移；迁移和运行权限分离时，先用 v0.7.3 执行 `server --migrate-only`，再执行 `server --check-migrations` 核对账本。无需人工转换业务数据。

## 回滚

v0.7.2 无法应用新版的缓存写入分档价格、Ultrafast 倍率及 OAuth 轮换保护。回退前暂停流量和汇总任务，保存升级后的用量、定价和凭据变更以便核对。新增列和索引具有默认值或允许空值；旧版对更新后汇总触发函数的完整回滚兼容性尚未验证。需要恢复至升级前状态时，使用一致的数据库、持久化数据及密钥备份，配合原镜像 Digest，评估备份后的写入和已轮换凭据。保留迁移账本和校验和。

## 部署契约

镜像目标平台为 `linux/amd64` 和 `linux/arm64`。服务监听 `0.0.0.0:8080`，健康检查为 `GET /health`，持久化目录为 `/app/data`。
